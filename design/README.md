# superdev Design Documents

superdev is a system that lets an AI team deliver software automatically: AI splits the tasks and writes the code; programs enforce the rules, run the flow, and close out the work. It grew out of its production-running predecessor bigdev and reworks the five problems bigdev exposed.

It fixes three old problems:

1. AI code changes keep failing regression tests → every round now starts from the "last all-green" state, a broken change rolls back entirely, and after two failures the worker must research before switching direction.
2. The flow relied on timer polling and was slow → any state change now advances the next step immediately, with no waiting for the next cycle.
3. Human decisions were scattered across chat logs → one click on the web page now decides, and it takes effect immediately.

## Glossary (read this first)

| Term | Meaning |
|---|---|
| ledger | The file record of tasks, decisions, and status; git-versioned; the system's single source of truth |
| green point | The commit where all of a module's tests pass |
| red-green discipline | Break it, roll it back: when tests go red (fail), roll back to the green point |
| event-driven | Act on occurrence: any state change automatically triggers the next step |
| projection | The query copy of the ledger in the database, generated by programs |
| hook | Call interceptor: program checks inserted automatically before/after an AI tool call |
| supervisor | The progress-watching program: reports when work stops advancing for a while |
| fanout | Distributing one backlog of to-dos into the ledgers of multiple projects |
| manager | The idea-producing AI session: splits tasks, judges acceptance, decides reassignment |
| worker | The doing AI session: writes code, tests, commits, opens merge requests |
