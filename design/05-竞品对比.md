# superdev 竞品对比（v4 · 论证版）

这份文档回答两个问题：superdev 该不该建；凭什么相信它能成为受欢迎的项目。每个结论都给出证据、最强反方和残余风险，不写没有出处的形容词。

## 先给结论：该不该建

**该建，而且"不建"这个选项实际不存在。** 三条论据：

1. **不建的真实含义是继续忍受。** "不建 superdev，改用成熟项目"这条路走不通：19 个开源项目没有一个能跑进我们的环境（私有 git、飞书通知、四种执行引擎、多仓项目）；唯一做任务级多仓分发的 Kepler 是闭源商业产品。剩下的选择只有"继续用 bigdev"，而 bigdev 的五个问题（回归不收敛、管理端违规、轮询延迟、升级太晚、引擎耦合）每天都在烧 token 和工时。
2. **三个品类空缺经过逐个核实，目前无人占据**（见下节，每个都做了最强反方压力测试）。
3. **建设的成本是改造在产系统，不是从零造轮子。** bigdev 骨架已在生产运行，superdev 的三件新武器（红绿纪律、hook 裁决、事件状态机）都是叠加上去的。

判断规则先说清楚：**superdev 不需要在每个维度赢过每个项目——那是不可能也不必要的。它需要在"无人覆盖、且用户最痛"的维度上独占，这比全面领先更接近受欢迎的真相。** spec-kit 只解决"规范写不清"一件事，就到了 120k 星。

实现路径是两条腿：**空位维度独占**（下面三个优势），**争维度拉平**（再下面的吸收清单——对手验证过的强项逐项搬进来）。拉平之后，"超越"才是全维度的事实，不是定位话术。

## 三个独有优势（各含最强反方与残余风险）

### 优势一：失败治理闭环——把"卡住"当成生命周期来管

**是什么。** 失败在 superdev 里是一等公民，有完整生命周期：失败预算（每任务最多两次试错）→ 强制研究（第二次失败先查资料，不许再猜）→ 结构化报告（程序自动拼"试过哪些方向"，带证据带成本）→ 升级专家（网页一键拍板）→ 自动恢复（指标回升即复工）。从第一次红到恢复，全程无人工盯守。

**为什么这是空缺。** 检索证实痛点极其普遍：AI 编排器陷入死循环是社区高频抱怨，OpenAI 官方论坛 2026 年 9 月还有"Astra 编排器卡死循环不派工"的 bug 报告；GitKraken 的多仓工具盘点直言"人工审查是瓶颈"。但 19 个项目没有一个把失败做成生命周期：编排器们止步于"重试"或"转人工"，没有一个有失败预算、强制研究、结构化试错报告和自动恢复的组合。

**最强反方。** 大厂（GitHub、Anthropic、OpenAI）随时可以给自家工具补上失败处理。

**回应。** 补丁和架构是两回事。现有工具把失败当"异常"处理（重试、报错、转人），superdev 把失败当"常态"设计（每任务都预设会失败，预算、研究、报告、恢复提前就位）。前者加功能追不上后者换世界观——就像"给马车加发动机"和"造汽车"的差别。且这套闭环的每个环节都在台账里留证据，追平者要连审计链一起追。

**残余风险。** 大厂可能追平"预算+升级"这个子集，砍掉我们的差异化。对策：把护城河压在"纪律组合 + 基准数字"上（见"受欢迎的路径"），数字公开且持续更新，后来者要赢的不是功能清单而是可复现的效果。

### 优势二：开源世界里唯一的多仓任务级编排

**是什么。** 一个项目的任务可以横跨多个仓库：拆出来的微任务按归属派进各仓的台账，各仓各自开分支、各自过门禁、各自合并；跨项目的横向改造（比如"所有项目改 docker 部署"）作为一个改造项目，待办 fanout（分发）进每个项目。一个仓库只归一个项目管，不打架。

**为什么这是空缺。** 2026 年 11 月 GitKraken 专门评了 7 个多仓 AI 编排工具，结论：只有它自家的 Kepler（闭源收费）做到"任务跨多仓"；其余 6 个（Orca、Emdash、Conductor、Superset、Claude Squad、Nimbalyst）要么单仓并行、要么只是工作区模式。开源界连"issue 分发到多仓"都没有成品，GitHub 官方讨论区的共识是"原生多仓还早，目前只能人肉拆成单仓子任务"——superdev 把这个人肉步骤自动化了。

**最强反方。** 多仓是不是小众需求？大多数开发者只有单仓。

**回应。** 企业和微服务场景天然多仓，需求大到 GitKraken 愿意为它做闭源产品来卖——这恰恰证明市场存在且开源侧空着。bigdev 已在生产跑 7 个仓（a 7-repo product），不是纸上设计。

**残余风险。** 单仓用户占多数，这个优势触达的是企业场景。对策：superdev 对单仓项目同样完整可用（bigdev 的 3d 项目就是单仓多会话），多仓是高端差异不是排他门槛。

### 优势三：收敛纪律内置在编排契约里，程序强制，不靠提示词

**是什么。** 红绿纪律（绿点开工、改坏整体退回）和研究纪律（事前预算、两败先研究）写进工人契约，由纪律脚本和派发器强制执行：从上次全绿的提交开分支是程序开的，退回是程序退的，"新策略必须引用研究结论"是程序查的。AI 想跳过纪律，跳不过程序。

**为什么这是空缺。** 纪律和编排至今分家：Aider 有完整红绿纪律但是单会话工具，管不了一队工人；编排器们管一队工人但没有纪律——Bernstein 门禁很硬，可它只拦住烂代码合不进去，帮不了工人变绿；Agent Orchestrator 会把 CI 失败日志喂回去重试，但没有退回绿点、没有强制研究、没有预算。把两者接起来，19 个项目里一个都没有。

**最强反方。** "这是布线，不是发明"——每个零件都有出处（Aider、troykelly、Bernstein），集成算什么创新？

**回应。** 用户从来不为"发明"付费，只为结果付费。Linux 是布线，iPhone 是布线——集成即产品，前提是集成解决了零件解决不了的问题。这里的问题是：纪律散装时（提示词里写"请先测试"），AI 会跳过；只有进契约、由程序强制，纪律才存在。这正是 superdev 提供而"自己拿 Aider 加看板拼"拼不出来的东西。

**残余风险。** "集成即产品"要靠效果数字兑现，空口说集成没用。对策与优势一相同：公开基准，可复现，持续更新。

### 底牌：唯一在生产且自举的系统

19 个项目无一个用自己开发自己；bigdev 已经在生产运行业务，superdev 的每处改动走自己的流水线交付。这意味着：文档里写的每个机制都在真实项目上跑过才留下来，不是 demo 机制。

## 吸收清单：把对手验证过的强项逐项搬进来

竞品对比的另一半用途是照镜子：对手的强项说明用户要什么，能吸收的全部吸收。下表是逐项决定，"落地方式"都进了详细设计 §8。

| 来自 | 它的强项 | superdev 怎么吸收 | 状态 |
|---|---|---|---|
| spec-kit | spec/plan/tasks 模板已成事实标准 | 台账直接兼容其格式：spec-kit 产出的计划原样导入即成任务清单 | §8.1 新增 |
| Kiro | recon（先侦察再动手） | 研究预算分档 | v2 已吸收 |
| Bernstein | 合并前质检管线（lint→类型→测试） | 门禁从"回归全绿"升级为每模块可配置的质检管线 | §8.2 新增 |
| Bernstein | 防篡改审计链（HMAC 链式日志） | 事件日志加链式签名，合并决策可离线验真 | §8.3 新增 |
| Agent Orchestrator | CI 失败自动捕获、喂回重试 | 合并请求开出后盯 CI，失败日志自动回喂工人一轮（现在只盯本地回归） | §8.4 新增 |
| Vibe Kanban | 看板视图、云协作 | 决策面加看板视图（首期）；云同步列路线图（非首期） | §8.5 部分 |

| Superpowers | 评审作为第二双眼 | 新增"评审工人"角色：diff 先过 AI 评审再进门禁 | §8.7 新增 |
| troykelly | 跨会话记忆（什么方法灵过） | research_notes 升级为模块级知识库：某仓灵过的改法自动注入后续任务的研究预算 | §8.8 新增 |
| Aider | 编辑引擎（diff 容错） | 引擎级硬骨头，后续按"拼引擎级"原则换件 | 挂账 |
| OpenHands | 版本节奏与云托管的运营 | 运营事项，列为团队任务（见残余风险第 3 条） | 挂账 |

**吸收之后的格局。** 争维度（规范、质检、CI 回喂、看板、澄清、评审、记忆）全部拉平——对手有的我们都有；空位维度（失败治理闭环、开源多仓 fanout、契约内强制纪律、事件状态机、自举）仍然独占。到这一步，"超越"的完整表述是：**并集之上加独占**。对手要追平我们只需补独占项（难，见三个优势的反方回应）；我们要追平对手只需按清单施工（易，都是已验证的成熟做法）。

## 反方总陈述与回应：spec-kit 已经赢了，为什么还要你

这是读完五层盘点后最自然的反对，单独回应。

spec-kit 的 120k 星赢在"先写对规范"——它管的是 build the right thing（做什么）。它到计划产出为止。superdev 管的是 land it green（把它落到测试全过、合进主干）——计划之后的执行可靠性。两者是流水线的上下游，不是对手：spec-kit 的产出可以直接喂进 superdev 的台账，我们甚至会提供这个适配器。用一个已经赢了的互补品的存在来否定下游空缺，就像用"设计工具已经很流行"来否定 CI/CD 的价值。

## 受欢迎的诚实路径

受欢迎不靠论证，靠前提条件加可证伪的证据。这一节列出全部前提和指标——做到就配得上信心，做不到就撤回这句话。

**定位（一句话）。** 别人的工具管派活，superdev 管把活干成：**执行可靠性层 / 失败治理层**。不与 spec-kit 抢"规划"，不与看板抢"管理"，占住"落地"。

**为什么这个定位有机会成为最受欢迎。**
1. 痛点最大：每一条"我的 agent 卡死循环烧 token"的帖子都在替这个定位做市场教育，社区抱怨的密度就是需求密度。
2. 赛道无王：编排器赛道至今没有赢家（Vibe Kanban 28.7k 星照样日落，AutoGen 6 万星照样归档），说明"再做一个看板/调度器"是死路；"失败治理"是没人占的新轴，先占者拿定义权。
3. 规模有先例：spec-kit 证明"痛点级方案"一年能从 0 涨到 12 万星；失败治理的痛点面不小于规范不清。

**四个前提条件（缺一不可）。**
1. 剥离私有耦合：GitHub/GitLab 适配器、通知通道可插拔（飞书只是其中一款）、英文文档。
2. 一条命令能装能跑，十分钟看到第一个任务全绿合并。
3. 公开基准（见下），数字摆在 README 第一屏。
4. 兼容策略：不要求换工具——能在 spec-kit 计划之上跑，能调用用户现有的 Claude Code/Codex 会话当工人。

**可证伪指标（发布即成立或推翻）。** 用同一批"易卡住"任务（含回归失败、依赖冲突类），对比开/关收敛堆栈：首回合绿率（first-attempt green rate）、每个合并 PR 的 token 成本（tokens per merged PR）、卡住任务的平均恢复时长、需要人介入的比例。竞品给不出这组数字——不是他们不会宣传，是他们没有能测这组数字的机器。这是我最硬的差异化证据。

**残余不确定性与止损线。**
1. 大厂追平核心子集 → 止损线：若半年内官方工具内置同等失败预算+升级，转向"多引擎中立 + 私有部署"细分继续做。
2. 纪律开销劝退简单用户 → 对策：trivial 任务零开销分档已有，基准里必须包含"简单任务开销 <5%"一栏，超了就改。
3. 社区运营能力未验证 → 这是团队问题不是产品问题，诚实列为最大未知数。

## 五层盘点（背景材料）

以下为全场地图，详细机制矩阵保留 v3 口径。

**A. 规范驱动层：[spec-kit](https://github.com/github/spec-kit)（~120k★，GitHub 官方，spec→plan→build）、AWS Kiro（商业 IDE，有 recon 先侦察阶段）、BMAD-method。** 同路人：验证了"规范先行+任务级上下文"，到计划为止；superdev 从计划的终点起步。

**B. 纪律技能层：[Superpowers](https://github.com/obra/superpowers)（~40k★，TDD 当每任务关卡）、[troykelly/claude-skills](https://github.com/troykelly/claude-skills)（开工前研究、两败即研究）。** 纪律的出处：superdev 把它们从"提示词里的建议"升级为"契约里的强制"。

**C. 编排器层：Bernstein（确定性调度+合并前质检）、Agent Orchestrator（CI 失败喂日志重试）、Vibe Kanban（28.7k★，已日落）、Emdash、Baton、Conductor 系、Claude Squad、Crystal/Nimbalyst、Open Multi-Agent；补入 GitKraken 盘点新增的 Kepler（闭源，唯一任务级多仓）、Orca、Superset。** 各握一块拼图，无失败治理、无开源多仓 fanout。

**D. 通用框架层：[MetaGPT](https://github.com/foundationagents/metagpt)（~71k★）、[CrewAI](https://github.com/crewaiinc/crewai)（~57k★）、[AutoGen→AG2](https://github.com/microsoft/autogen)（~62k★，原仓归档）、[OpenHands](https://www.promptquorum.com/power-local-llm/openhands-review)（~77k★）。** 造智能体的库，不面向真实仓库交付；superdev 站在其上取引擎级组件。

**E. 工具级：[Aider](https://aider.chat/docs/config/options.html)（~30k★）。** 红绿纪律出处，单会话；纪律级移植。

## v1→v4 调研方法留档

v1 教训：按产品品类搜词，漏掉规范驱动和纪律技能两层。v2 起按机制逐个搜。v4 新增一步：**每个"独有优势"发表前做反方压力测试**——专门搜"有没有人已经做了"，找到 Kepler 就补进对比，找不到才敢写"空缺"。声称独有之前，先尝试证伪。
